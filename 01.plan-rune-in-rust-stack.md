# rune in Rust — recommended stack, July 2026

## Context

`rune` is a ~69k-LoC Go/Bubble Tea markdown editor whose defining paradigm is **preview fused with edit**: markdown is rendered in place, and syntax delimiters conceal/reveal as the cursor enters and leaves each token. Everything downstream — `SyntaxSpan.CellMap` (per-visual-cell → buffer byte offset), `BufferToSyntax`/`SyntaxToBuffer` offset deltas, `hiddenRange` cursor clamping — exists to serve that one behaviour.

This document selects a Rust stack against three stated goals (blazing-fast TUI rendering, pedantically correct markdown + HTML, bulletproof SQLite), judged against rune's actual code rather than in the abstract.

**Every claim below was fetched live this session.** Sources are linked inline. Nothing is asserted from prior knowledge.

**User decisions taken as given:**
- **Buffer enforces valid UTF-8.** Non-UTF-8 files are refused or repaired at load with a surfaced error. This unlocks `&str`-based parsers and `ropey`, at the cost of weakening §1.4.5 for non-UTF-8 inputs.
- Parser choice was delegated to investigation; the finding is below.

## The three pillars

### 1. TUI — `ratatui` 0.30.2 on the `termina` backend

| Crate | Version | Date | Evidence |
|---|---|---|---|
| `ratatui` | 0.30.2 | 2026-06-19 | [crates.io](https://crates.io/api/v1/crates/ratatui) — 14.99M recent / 39.68M total downloads |
| `ratatui-termina` | 0.1.0 | 2026-06-19 | [crates.io](https://crates.io/api/v1/crates/ratatui-termina) |
| `termina` | 0.3.3 | 2026-05-30 | [crates.io](https://crates.io/api/v1/crates/termina) — 1.20M of 1.24M downloads are *recent* |
| `ratatui-image` | 11.0.6 | 2026-06-25 | [crates.io](https://crates.io/api/v1/crates/ratatui-image) |

**Why ratatui.** Its `Buffer` is `{ area: Rect, content: Vec<Cell> }`, and `diff`/`diff_iter` "[builds] a minimal sequence of coordinates and Cells necessary to update the UI from self to other" ([docs.rs](https://docs.rs/ratatui/latest/ratatui/buffer/struct.Buffer.html)). This is structurally the same model rune already has (`textedit.Cell{Rune, Grapheme, Width, Style, BufOffset, …}`), so the port is a translation, not a redesign.

It also deletes rune's worst hot path. `cellsToString` currently compares adjacent cell styles via `stylesEqual(a,b) → a.Render(" ") == b.Render(" ")` — **two full ANSI renders plus a string compare per adjacent cell pair, per line, per keystroke**. Ratatui's `Cell` holds `symbol / fg / bg / modifiers` as plain comparable values, so run-coalescing becomes a value comparison. `diff_iter` avoids the intermediate `Vec`.

**Why the termina backend specifically — this is the non-obvious call.** Helix switched its terminal backend from crossterm to termina ([PR #13307](https://github.com/helix-editor/helix/pull/13307)), and `termina` is maintained by the helix-editor org. Its rationale, quoted from the [README](https://github.com/helix-editor/termina): *"Termina is a cross between Crossterm and TermWiz with a lower level API which exposes escape codes to consuming applications… The aim is to scale well in the long run as terminals introduce VT extensions like the Kitty Keyboard Protocol."*

The decisive capability: **crossterm cannot read VT responses**, so request/response escapes like DECRQSS never come back. Termina can. That directly fixes a standing weakness in rune — `pkg/terminal/terminal.go` today detects Kitty graphics, truecolor and OSC52 by **sniffing `TERM_PROGRAM`/`KITTY_WINDOW_ID`/`WEZTERM_PANE` env vars with no escape probing at all**. Termina replaces guessing with querying.

Helix pins `termina = "0.3"` in its [workspace manifest](https://github.com/helix-editor/helix/blob/master/Cargo.toml) and ships it in a production editor.

**Images.** `ratatui-image` 11.0.6 covers "sixels, kitty, iterm2, and unicode-halfblocks" and now lives under the ratatui org. rune's Kitty *Unicode-placeholder* scheme (`U+10EEEE` + combining diacritics, image ID smuggled in the 24-bit fg colour) is unusual enough that this needs a spike (see Risks) — but the iTerm2 OSC 1337 path and protocol detection come free.

**Counter-evidence, stated plainly.** OpenAI's Codex TUI does *not* use this: it pins `ratatui = "0.29.0"` and `crossterm = "0.28.1"` **through git forks** (`nornagon/ratatui`, `nornagon/crossterm`) in [`codex-rs/Cargo.toml`](https://github.com/openai/codex/blob/main/codex-rs/Cargo.toml), plus ratatui unstable features (`scrolling-regions`, `unstable-backend-writer`, `unstable-rendered-line-info`). Read this as: a demanding TUI outgrew stock ratatui 0.29. Much of what they forked for is what 0.30 + termina now address upstream, but budget for the possibility of needing a patch.

**Architectural gap to plan for:** ratatui is immediate-mode and ships **no runtime** — no `tea.Program`, no `Msg`/`Cmd` loop. rune's Bubble Tea + HSM structure must be hand-written. Helix and Codex both own their event loops. This is the single largest non-mechanical part of the port.

### 2. Markdown + HTML — `comrak` 0.54.0

| Crate | Version | Date | Evidence |
|---|---|---|---|
| `comrak` | 0.54.0 | 2026-07-12 | [crates.io](https://crates.io/api/v1/crates/comrak) — 1.72M recent downloads |
| `html5ever` | 0.39.0 | 2026-03-13 | [crates.io](https://crates.io/api/v1/crates/html5ever) — 27.4M recent downloads |

This was the contested choice. Judged against the **preview-fused-with-edit** paradigm rather than raw throughput, it is not close.

**The criterion.** Reveal/conceal needs the byte range of the *delimiters*, not just the node — to conceal `](url)` while showing `text`, and to map every rendered cell back to a buffer offset. Whichever parser cannot expose precise **inline** sub-spans cannot support rune's core behaviour at all.

**Why comrak wins:**

1. **Inline sourcepos is a first-class, hardened feature.** From the [CHANGELOG](https://github.com/kivikakk/comrak/blob/main/CHANGELOG.md): reintroduced as experimental in **v0.26.0** (2024-07-12); accuracy work in **v0.27.0** ("Track line offsets for better accuracy of inline sourcepos"); **v0.38.0** (2025-04-05) — *"experimental-inline-sourcepos: not really experimental any more!"*; then continuous fixes through v0.46.0/0.47.0/0.48.0 (Oct–Nov 2025) for description lists, HTML blocks, multiline block quotes, escaped character spans, lists, unclosed fenced code blocks. Two years of dedicated investment in exactly the feature rune depends on.

2. **Sourcepos columns are UTF-8 *byte* offsets by default.** The CLI opt-out is `--sourcepos-chars`, which "reports column positions in sourcepos as a Unicode character count rather than UTF-8 byte offsets". Combined with rune's existing `Buffer.lineStarts` index, `(line, byte-column) → absolute byte offset` is a lookup and an add — a direct port of the current design, honouring §1.5 (offsets are bytes).

3. **Proven compliance.** [README](https://github.com/kivikakk/comrak): "CommonMark: 652/652" and "GFM: 670/670" against CommonMark **0.31.2**. This is the only candidate publishing an actual pass count.

4. **It natively implements rune's hand-rolled extensions.** Per the CHANGELOG: wikilinks (v0.24.0), **GitHub-style alerts/admonitions** (v0.34.0) — rune's `> [!callout]`, math (v0.22.0), front matter (v0.9.1), plus footnotes, description lists, spoiler text, superscript, CJK-friendly emphasis. This deletes `markdown_advanced.go` and `markdown_frontmatter.go` outright.

5. **It has an AST** (`typed_arena` + `RefCell`), walkable the way rune already walks goldmark's.

**Why pulldown-cmark was rejected despite being faster.** [Issue #441](https://github.com/pulldown-cmark/pulldown-cmark/issues/441) — **still open** — establishes that `into_offset_iter()` yields ranges for whole elements only and *cannot* give sub-ranges for a link's destination or title; the title is `CowStr::Inlined`, so recovering its offset needs unreliable string searching. That is precisely the sub-span reveal/conceal requires. Its compliance is also only a stated *goal* — the [README](https://github.com/pulldown-cmark/pulldown-cmark) says "the goal is 100% compliance" with no published pass rate — and it lacks wikilinks, callouts and math, so the hand-rolled parsers would survive. Fast, but structurally wrong for this paradigm.

**Why markdown-rs was rejected.** `markdown` 1.0.0 is attractive on paper (real SemVer 1.0, 100% safe Rust, claims 100% CommonMark + GFM + MDX, `mdast::Html` retains raw HTML with position). But [`unist::Point`](https://docs.rs/markdown/latest/markdown/unist/struct.Point.html) documents `offset` as *"0-indexed integer representing a **character** in a source file"* — characters, not bytes. Betting the offset-mapping core on a field whose own docs contradict §1.5 is not worth it when comrak states byte semantics explicitly.

**HTML.** rune today does **not** handle raw HTML: the goldmark AST walk has no `ast.RawHTML`/`ast.HTMLBlock` arm, so HTML falls through to plain `TokenText`. comrak parses raw HTML per CommonMark (scrubbing by default; `unsafe_` to retain) — that alone is an upgrade. For *pedantic* HTML tokenisation (syntax-highlighting HTML blocks properly), add `html5ever` 0.39.0, Servo's "high-performance browser-grade HTML5 parser", applied only to the text of HTML block nodes.

### 3. SQLite — `rusqlite` 0.40.1, `bundled`

| Crate | Version | Date | Evidence |
|---|---|---|---|
| `rusqlite` | 0.40.1 | 2026-06-06 | [crates.io](https://crates.io/api/v1/crates/rusqlite) — 27.0M recent / 84.6M total |

**The whole argument is one bug.** Per [sqlite.org/wal.html](https://www.sqlite.org/wal.html), the **WAL-reset bug** is a data race where a second checkpoint fails to notice the WAL was reset, mis-sets the WAL-Index header, and a later checkpoint skips part of a committed transaction — **corrupting the database file**. Affected: **3.7.0 (2010-07-21) through 3.51.2 (2026-01-09)**. Fixed in **3.51.3 (2026-03-13)** (backports 3.44.6, 3.50.7).

rusqlite 0.40.1 with `bundled` ships **SQLite 3.53.2** — past the fix, with a vendored, reproducible, statically-linked build rather than whatever the host has. This is not theoretical diligence: OpenAI's Codex carries the comment *"Keep SQLx's bundled SQLite on a version containing the WAL-reset corruption fix"* against its `libsqlite3-sys` pin.

**Feature flags**, mapped to rune's actual `pkg/docstate` usage, quoted from the [README](https://github.com/rusqlite/rusqlite):
- `bundled` — vendored SQLite; removes host-version variance
- `blob` — "gives `std::io::{Read, Write, Seek}` access to SQL BLOBs" → streaming the zstd content blobs
- `backup` — "allows use of SQLite's online backup API"
- `hooks` — "for Commit, Rollback and Data Change notification callbacks"
- `limits`, `functions`, `trace`, `serialize`

**Direct mapping of the existing store.** rune already sets `_foreign_keys=on&_txlock=immediate&_busy_timeout=5000` and `SetMaxOpenConns(1)`. In rusqlite that is one `Connection` behind a mutex, `PRAGMA journal_mode=WAL`, `PRAGMA foreign_keys=ON`, `busy_timeout(5s)`, and `TransactionBehavior::Immediate`. One-to-one.

**Rejected, with reasons:**
- **`turso` 0.7.1** ([crates.io](https://crates.io/api/v1/crates/turso), latest is `0.8.0-pre.1`) — the clean-room Rust rewrite. Genuinely interesting (MVCC, async I/O) but pre-1.0 and shipping pre-releases weekly. rune's prime directive is protecting the user's words; a young storage engine is the wrong place to be early.
- **`libsql` 0.9.30** ([crates.io](https://crates.io/api/v1/crates/libsql), `0.10.0-pre.4` unreleased) — production-ready, but its value is embedded replicas and remote sync. rune is a local single-process editor; that's surface area with no benefit.
- **`sqlx`** — Codex's choice, but it's async and drags tokio into persistence. rune's docstate is deliberately synchronous on a single connection. rusqlite matches the existing invariants without inverting the I/O model.

## Risks and required spikes

Ordered by how much they could invalidate the above. Each should be a timeboxed spike **before** committing to the port.

1. **Kitty Unicode-placeholder images.** rune encodes image IDs in the 24-bit foreground colour of placeholder cells and must never dim those rows. Verify `ratatui-image` 11.x supports the Unicode-placement (`U=1`) variant, or plan to keep emitting raw escapes out-of-band as today. *Highest risk — unverified.*
2. **Ropey's stable release is from October 2023.** 2.0 has been in alpha/beta since 2024. Confirm 1.6.1 meets needs, or evaluate `crop` 0.4.3 (2025-04, but only 62k recent downloads vs ropey's 3.9M).
3. **comrak reparse cost.** comrak's own README: *"Comrak is not and will not be the fastest: some alternatives do not construct an AST."* rune reparses the **entire buffer on every keystroke** and has **zero benchmarks** (`grep "func Benchmark"` → no results). Benchmark comrak full-reparse on a large document early. Mitigation if it fails: block-level dirty-region reparse, since sourcepos gives exact block boundaries.
4. **The Bubble Tea runtime has no Rust equivalent.** ratatui provides no message loop. Scope the HSM + `Msg`/`Cmd` port explicitly rather than assuming a library.
5. **UTF-8 enforcement is a user-visible behaviour change.** Specify the load-time policy (refuse vs. lossy-repair-with-banner) and confirm it against §1.4.5 before writing code.
6. **goldmark panic-recovery has no analogue.** `parseMarkdown` wraps goldmark in `defer recover()` for a known indexing bug. Rust panics can't be caught the same way; define the equivalent failure behaviour (§1.3 forbids losing the buffer to a panic).
7. **Codex's forks are a warning.** A high-profile TUI needed patched ratatui + crossterm. Verify 0.30/termina covers your needs before depending on stock crates.

## Verification plan

1. **Spike 1 — offset fidelity (blocking).** Feed a document exercising every rune token kind (nested `**[x](y)**`, wikilinks, callouts, inline/block math, frontmatter, tables, CJK + emoji for multi-byte columns) through comrak with `sourcepos` on. Assert every inline node's `(line, col)` → absolute byte offset via `lineStarts` round-trips to the exact source bytes. **If this fails, the whole markdown choice is void.**
2. **Spike 2 — render throughput.** Port `textedit`'s cell pipeline onto `ratatui::Buffer` for one document. Benchmark full sync + `diff_iter` at 80×24 and 200×60 against a 5k-line file. Establish the benchmark rune currently lacks.
3. **Spike 3 — terminal capability query.** Use termina to probe Kitty-graphics/keyboard and truecolor support by escape query in Ghostty, Kitty, WezTerm, iTerm2 and Terminal.app; confirm it beats today's env-var sniffing.
4. **Spike 4 — durability.** Port `materialize.go`'s six-step CAS write onto `rusqlite` + `libc::renamex_np`. Confirm `RENAME_SWAP`/`RENAME_EXCL` constants and `EOPNOTSUPP` → `ErrUnsupported` mapping on an SMB mount. Verify `SELECT sqlite_version()` reports ≥ 3.51.3.
5. **Spike 5 — merge parity.** Run rune's existing merge corpus through `diffy::merge_bytes` with diff3 `ConflictStyle`; confirm `hunks.go`'s marker parser still matches.
6. **Port the fuzz harness first.** rune has 18 fuzz targets and 879 tests. `cargo-fuzz` equivalents of `FuzzSyntaxMapRoundtrip`, `FuzzWrapMapRoundtrip`, `FuzzTwoSessionsSharedDoc` and `FuzzSaveRace` should exist *before* the port is trusted — they are the invariant net that makes this safe.

## Answer in one line

**ratatui 0.30.2 on termina 0.3.3 · comrak 0.54.0 (+ html5ever for HTML blocks) · rusqlite 0.40.1 bundling SQLite 3.53.2** — chosen because termina is the only backend that can *query* terminal capabilities instead of guessing, comrak is the only parser with hardened, byte-offset inline source positions (the one feature rune's preview-fused-with-edit paradigm cannot exist without), and 3.53.2 is the first widely-vendored SQLite past the WAL-reset corruption bug that affected every release from 2010 to January 2026.
