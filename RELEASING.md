# Releasing

Rune ships through two chained GitHub Actions workflows:

1. **Cut Release** (`cut-release.yml`, manual dispatch) — runs `cargo release` to bump
   `crates/rune-cli/Cargo.toml` and `Cargo.lock`, commits and pushes that to `main`
   (no tag; tagging is disabled in `[workspace.metadata.release]`), then dispatches
   the release pipeline with `tag=v<version>`.
2. **Release** (`release.yml`, generated by `dist generate` from `dist-workspace.toml`,
   `dispatch-releases = true`) — verifies the tag matches the crate version, builds the
   `aarch64-apple-darwin` artifact, creates the GitHub Release (**which creates the
   tag**), and pushes the `rune` formula to `aka-rider/homebrew-tap`.

The version lives in exactly one place: `crates/rune-cli/Cargo.toml`. The tag is
derived from it and is never created by hand.

## One-time setup

- Create a GitHub personal access token with `repo` scope that can push to
  `aka-rider/homebrew-tap`, and add it as repo secret `HOMEBREW_TAP_TOKEN` on
  `aka-rider/rune`. (This is a different secret name from the Go pipeline's
  `HOMEBREW_TAP_GITHUB_TOKEN`; the same PAT can back both.)
- If `main` is branch-protected, allow `github-actions[bot]` to push to it —
  Cut Release pushes the version-bump commit directly.

## Per release

1. Make sure everything you want to ship is merged to `main` and pushed — the release
   builds `main` HEAD. Releasing before the Rust tree reaches pushed `main` would
   release whatever is there instead.
2. GitHub → Actions → **Cut Release** → Run workflow → enter the version
   (e.g. `1.3.0`, no leading `v`).
3. Watch the chained **Release** run finish, then verify:
   ```sh
   brew update
   brew install aka-rider/tap/rune
   rune --version
   ```

## Dry run

Actions → **Release** → Run workflow with the default `dry-run` tag: runs the plan and
build steps against `main` without publishing or announcing anything.

## Local checks

```sh
dist plan --tag=v<version>   # what a release of <version> would produce
dist generate --check        # release.yml is in sync with dist-workspace.toml
```
